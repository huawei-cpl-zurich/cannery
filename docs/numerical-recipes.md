# Reproducible numerical input recipes

Numerical verification uses service-owned recipes instead of arbitrary Python
input generators. This module defines recipe generation only; ingress reference
caching and candidate validation are integrated in subsequent slices. Existing
Python case generators remain unchanged and diagnostic.

A recipe suite has `schema_version: 1`, `generator: sha256-f32-v1`, and one to
32 ordered cases. Each case has a unique lower-case identifier and exactly one
named float32 tensor input. Input names use the same identifier grammar as specs.
Each tensor declares a shape (one to four dimensions), an explicit unsigned
64-bit seed, and `uniform_f32`, `arange_f32`, or `zeros_f32` distribution. Shapes
are limited to 1,048,576 elements per tensor and aggregate inputs to 32 MiB.

```yaml
schema_version: 1
generator: sha256-f32-v1
cases:
  - id: small
    inputs:
      x: {shape: [2, 3], distribution: uniform_f32, seed: 42}
  - id: strided
    inputs:
      x: {shape: [4, 3], distribution: arange_f32, seed: 42, layout: transpose}
  - id: empty
    inputs:
      x: {shape: [0, 3], distribution: zeros_f32, seed: 42}
```

For uniform values, SHA256 block `i` hashes this concatenation:

- ASCII `cannery-input-v1` followed by a NUL byte;
- the seed as unsigned little-endian uint64;
- UTF-8 case identifier, NUL, input name, NUL;
- block index as unsigned little-endian uint64, starting at zero.

Read each digest as eight little-endian uint32 words. Each word `w` yields
`((w >> 8) - 2**23) * 2**-23`, encoded as little-endian float32. These values
are exactly representable, lie in `[-1, 1)`, and require no library RNG. Discard
unused trailing words. Changing this algorithm requires a new generator version.

Arange starts at zero with step one; zeros contains positive zero. The seed is
explicit even for these distributions. Default layout is contiguous. A transpose
layout requires a 2-D logical shape: generate a reversed-shape backing tensor,
then transpose it to the declared shape. Thus arange `[4, 3]` produces logical
rows `[0,4,8]`, `[1,5,9]`, `[2,6,10]`, `[3,7,11]`. Consumers reconstruct that view,
including its strides; generated bytes are in logical contiguous element order.

Suite identity hashes canonical sorted compact JSON, including every recipe
field and generator version. Input identity hashes the canonical shape/dtype/
layout descriptor, a NUL separator and logical float32 bytes. Persist those
identities and recipes, not input tensor contents. Empty tensors have no value
bytes but still bind shape and layout in their input hash.
