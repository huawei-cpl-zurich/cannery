# Offline backup, restore and artifact maintenance

M7a adds explicit operator maintenance on a local Docker Compose deployment.
It does not run kernels, regenerate baselines, publish submissions or start
restored services. A3 support and the UI redesign remain separate work.

## Prepare a maintenance window

Use the same reviewed source, Compose overlays and private operator environment
as the running deployment. Stop incoming mutations and all application writers;
PostgreSQL and Redis may remain running. Stop the artifact service as well.
For the standard six-overlay deployment:

```bash
C=(docker compose --env-file ~/.config/cannery/service.env
   -f compose.yaml -f compose.artifacts.yaml -f compose.builds.yaml
   -f compose.numerics.yaml -f compose.benchmarks.yaml -f compose.releases.yaml)
"${C[@]}" stop api registrar builder validator benchmarker publisher worker reconciler artifacts
```

The tools refuse running/paused/restarting application containers and running
containers that can write the selected data volumes. Keep other operators and
external controllers from writing the database or volumes during maintenance.
Idle polling coordinators handle SIGTERM and stop dispatching new jobs. Current
bounded operations may finish; interrupted remote work retains its durable
receipts and normal lease/deadline recovery rules. This is not a remote-job
cancellation command.

## Capture and verify

```bash
cannery maintenance backup --project cannery --output /secure/backups/cannery-2026-11-13
cannery maintenance verify-backup /secure/backups/cannery-2026-11-13
"${C[@]}" up -d --no-build
```

Restart the original services after a failed capture too. Capture never stops
or starts services itself. An existing destination is never replaced. Failed
copies do not publish a completed backup. Files, staging directory and parent
publication are synced before success is reported.

The private backup directory contains a custom PostgreSQL dump, Git snapshots,
private artifact bytes, and build/baseline controller journals when those services
are configured. The manifest records exact file sizes/hashes, schema version,
PostgreSQL version, creation time and source container image IDs. Journal files
preserve remote operation handles across controller loss. Files use mode 0600
inside a 0700 directory; keep off-host copies under suitable access controls.

Operator environment secrets, SSH credentials, remote registry/device policy,
worker profiles, pinned loader wheels and toolchains are managed separately.
Record and recover those alongside the reviewed deployment source and images.
Redis is dispatch state: durable SQL/journals retain work, and reconciliation
reconstructs deliveries subject to original deadlines. No deadlines are extended
or baselines regenerated by restore.

Verification checks exact file sets, checksums and a bounded uncompressed tar
format before restore. It rejects unsafe paths, links/devices/sparse entries,
conflicting file/directory paths and unbounded extension metadata. PostgreSQL 17
and named Docker data volumes are supported. The initial archive budget is
1 TiB total, with bounded member/path inventories. Checksums detect corruption;
database dumps remain trusted operator input, not authenticated by the checksum
manifest alone.

## Restore drill or recovery

Create a **different, isolated Compose project** with fresh, project-owned named
volumes and an empty PostgreSQL database. Prepare matching database roles and
operator configuration; use the reviewed compatible application/images/runtime.
Create its application containers without starting them, then start PostgreSQL
only. For example, with an isolated environment and available images:

```bash
# T is a Compose command array like C, but uses an isolated environment/project.
"${T[@]}" create --no-build
"${T[@]}" up -d postgres
cannery maintenance restore /secure/backups/cannery-2026-11-13 --project cannery-drill
```

The restored project name must differ from the recorded source. Restore refuses
nonempty application databases/volumes, foreign-owned volumes, live writers,
role-layout changes and PostgreSQL major-version mismatches. It does not drop
or overwrite an existing database. SQL import uses one transaction and stops on
errors; archive files are verified before writes and again after transfer.
Permissions and owner IDs are preserved, so prepare the corresponding operator
UIDs/roles. If a restore fails, leave the target stopped and recreate fresh empty
target volumes/database before retrying; never treat a partial target as ready.

Verify retained SQL state, Git snapshot contents, private blob hashes and journal
handles before resuming anything. A drill must not start restored remote
coordinators: their copied handles refer to original remote operations. For an
actual promotion, fence the original deployment first so only one controller
owns the recovered work, then resume with its registered runtime configuration.
Restore itself never starts workers, executes submitted source or changes
private/published visibility.

## Audit and collect aged orphan blobs

With writers stopped:

```bash
cannery maintenance audit-artifacts --project cannery
cannery maintenance gc-artifacts --project cannery \
  --backup /secure/backups/cannery-2026-11-13
# Explicit application, only after reviewing the preview:
cannery maintenance gc-artifacts --project cannery \
  --backup /secure/backups/cannery-2026-11-13 --apply
```

The default minimum age is seven days; `--age-hours` cannot be below 24. All
retained SQL rows, including failures, historical results and withdrawn releases,
and controller journals protect referenced hashes. Private references must have
available matching objects. Missing/corrupt live data, unknown store files,
symlinks, scan-budget exhaustion or unavailable storage stop collection.

Only old unreferenced content-addressed blobs and recognized upload temporaries
are candidates. Explicit deletion requires a verified backup from the same
project containing identical bytes for **every** candidate. Reachability is
rechecked immediately before deletion, and each file's identity/content is checked
again inside the offline helper. The artifact directory is synced afterward.
Interrupted collection can be audited and retried; already deleted orphan bytes
remain in the backup. There is no online GC service or automatic production
cleanup. Save the JSON command output as the operator's maintenance evidence.

## Validation

```bash
pytest -q tests/test_backup_archive.py tests/test_backup_capture.py tests/test_backup_restore.py
pytest -q tests/test_artifact_audit.py tests/test_artifact_collect.py tests/test_shutdown.py
CANNERY_BACKUP_DOCKER=1 pytest -q tests/test_backup_docker.py tests/test_shutdown_docker.py
```

The Docker drills use isolated source/target projects, restore actual PostgreSQL,
Git, blobs and journals, simulate database unavailability, replay duplicate work
from independent containers, and verify PID-1 shutdown without a forced kill.
Artifact collection tests delete only their own backed-up orphan fixtures. These
are CPU/coordination checks; they do not establish new A3/A5 kernel behavior.
