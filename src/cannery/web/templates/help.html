Help & quickstart

Install the clients, sign in with your CANNery account, and choose a published kernel to download or run. No Hugging Face account is needed.

1. Install the CLI

Use Python 3.12 or newer and Git. A separate environment is enough for downloads; an NPU is not required.

python3.12 -m venv .venv-cannery
. .venv-cannery/bin/activate
python -m pip install 'git+https://github.com/huawei-cpl-zurich/cannery.git'

Client source: Cannery CLI · Python kernel client.

Use the same server URL for login and HF_ENDPOINT, including host and port. localhost refers to the machine running the client; remote clients need a reachable HTTPS address for this installation.

3. Download a published kernel

Open Global Best, select the device and kernel, and open an implementation. The Download button saves its verified binary archive. The arrow beside it contains commands pinned to that exact release.

Choose CLI · download only to cache the package and manifest without loading native code. Its runtime JSON describes the release’s target, so the CLI can download on a CPU machine. Keep the manifest with the package.

{% if hub_enabled %}

4. Install the Python / Hugging Face client

In the Ascend environment that will run the kernel, use Python 3.11 or newer and the release’s exact PyTorch, torch-npu and CANN versions. Keep those installed runtime versions. These source installs require Git and current stable Rust/Cargo; operator-provided wheels can be used instead.

python -m pip install \
  'git+https://github.com/huawei-cpl-zurich/cannery-kernels.git#subdirectory=kernels' \
  'git+https://github.com/huawei-cpl-zurich/cannery-kernels.git#subdirectory=cannery-runtime' \
  'huggingface-hub==1.33.0'

Copy and run Python · Hugging Face from the release’s download menu in this environment. It sets HF_ENDPOINT, downloads the pinned package and loads it with explicit trust. The client uses your CLI sign-in from the same machine and user account.

5. Run the loaded kernel

After the release snippet creates kernel, call its entrypoint with supported inputs. This example uses the current unary float32 interface; replace the example shape with one supported by your release. A3 and A5 packages require their matching device/runtime.

import torch
import torch_npu

shape = (2, 3)  # Choose a shape listed on the release page.
x = torch.randn(shape, device="npu", dtype=torch.float32)
y = kernel.forward(x)
torch.npu.synchronize()
print(y)

If a download fails

Sign-in required: browser and CLI sessions are separate. Run the CLI login command for the same origin used by the client. Explicit HF_TOKEN overrides the saved CLI credential.

Runtime mismatch: select a release matching the device and exact runtime shown on its page. Static CATLASS releases accept only their listed shapes.

Release unavailable: withdrawn releases cannot be downloaded again. Retry a transient connection failure; a download does not submit, rebuild, benchmark or publish a kernel.
